# ใช้ SENTINEL เป็นผลงาน Portfolio อย่างน่าเชื่อถือ

## ชื่อและคำอธิบายผลงาน

**SENTINEL — Security Event Monitoring & Threat Detection System**

ผมพัฒนาระบบติดตามเหตุการณ์ด้านความปลอดภัย เพื่อช่วยให้ผู้ดูแลเห็นความผิดปกติของการเข้าสู่ระบบและการใช้สิทธิ์จากข้อมูลที่กระจัดกระจาย ระบบรวบรวมเหตุการณ์ วิเคราะห์ด้วยกฎ ตรวจสอบหลักฐาน และบันทึกผลการสอบสวนผ่าน Dashboard ซึ่งเชื่อมต่อ Backend และฐานข้อมูลจริง

ผลงานนี้เชื่อมความสนใจด้าน Programming และ Cybersecurity เข้ากับปัญหาทางธุรกิจ ได้แก่ การดูแลบัญชีผู้ใช้ การจัดลำดับความเสี่ยง และการสื่อสารผลให้ผู้เกี่ยวข้องเข้าใจ การพัฒนาใช้ AI ช่วยเขียนและตรวจโค้ด จึงควรระบุส่วนที่ตนเองศึกษา ทดลอง แก้ไข และอธิบายได้จริง ไม่อ้างว่าเขียนเองทั้งหมดโดยไม่ใช้เครื่องมือ

## จัดหน้าในพอร์ตที่มีพื้นที่จำกัด

ใช้ประมาณ 1 หน้า:

- ชื่อโปรเจกต์ + ประโยคอธิบายปัญหาของธุรกิจ 2 บรรทัด
- ภาพ Dashboard ที่เนียร์เปิดและตรวจด้วยตัวเองหลังตั้งค่า บอกชัดว่าเป็น Demo dataset
- บทบาทและเทคโนโลยี: React, FastAPI, SQLAlchemy, SQLite, Argon2id, Pytest
- กระบวนการสั้น ๆ: เก็บเหตุการณ์ → ตรวจจับรูปแบบ → สอบสวน → รายงาน
- หลักฐาน: จำนวนเทสต์ที่ผ่านจากรายงานจริง, ตัวอย่างเงื่อนไขตรวจจับ, ประวัติ Alert
- QR ไปยัง Git repository/วิดีโอสาธิต/หน้าอธิบายฉบับเต็มที่สร้างและเผยแพร่จริงในภายหลัง

อย่าใช้ QR ที่ยังไม่มีปลายทาง และอย่าใส่ลิงก์ localhost เป็นเว็บไซต์ออนไลน์

## สิ่งที่ควรอธิบายโค้ดได้

| ประเด็น | ไฟล์ที่เปิดอธิบาย | คำถามฝึกตอบ |
| --- | --- | --- |
| Password hashing | backend/app/security.py | ทำไม hash จึงต่างจากการเข้ารหัสที่ถอดกลับได้? |
| Sessions | routers/auth.py, dependencies.py | ทำไม Cookie เป็น HttpOnly และเก็บเพียง token hash ใน DB? |
| CSRF | main.py, dependencies.py, frontend/src/api.ts | Cookie ส่งอัตโนมัติ ทำไมต้องตรวจ Origin และ CSRF อีก? |
| RBAC | dependencies.py | ถ้าผู้ใช้ข้าม UI มาเรียก API เองจะเกิดอะไรขึ้น? |
| Detection | services/detection.py | 5 ครั้งใน 60 วินาทีหมายถึงอะไร และทำไมไม่แจ้งเตือนทุกครั้ง? |
| Database | models.py, migrations/ | เหตุใดไม่เก็บทุกอย่างไว้ในตารางเดียว? Migration ช่วยอย่างไร? |
| Alert update | routers/monitor.py | ทำไมต้องส่ง expected_updated_at? |
| Reports | routers/reports.py | CSV formula injection คืออะไร? |
| Frontend | src/pages/Overview.tsx | ตัวเลขมาจาก API ใด และเมื่อ API ล้มเหลวแสดงอย่างไร? |
| Testing | backend/tests/ | เทสต์พิสูจน์อะไร และอะไรที่ยังพิสูจน์ไม่ได้? |

## โครงสาธิตสำหรับกรรมการ

“ผมเริ่มจากความสงสัยว่า ถ้ามีคนพยายามเข้าสู่ระบบหลายครั้ง ผู้ดูแลจะมองเห็นและตัดสินใจได้อย่างไร จึงสร้าง SENTINEL ที่เปลี่ยนเหตุการณ์ Login ให้เป็นข้อมูลสำหรับตรวจสอบครับ”

เปิด Demo dataset แล้วค้นหา `192.0.2.42` อธิบายว่า IP นี้เป็นตัวอย่างสำหรับเอกสาร ไม่ได้โจมตีเครื่องใคร แสดงกฎ AUTH-001 และหลักฐาน 5 ครั้งขึ้นไป เปลี่ยนสถานะพร้อมหมายเหตุ เปิดประวัติ แล้วส่งออกรายงาน PDF

“ระบบนี้ยังไม่ตัดสินว่าเป็นการโจมตีแน่นอน เพราะผู้ใช้ลืมรหัสผ่านหรือใช้เครือข่ายร่วมกันก็ทำให้เกิดรูปแบบคล้ายกันได้ ผมจึงออกแบบให้คนตรวจหลักฐานและบันทึกผลก่อนครับ”

## งานต่อยอดที่ทำด้วยตัวเองแล้วอธิบายได้

1. ปรับช่วงเวลา AUTH-004 ให้เหมาะกับธุรกิจจำลอง และเขียนเทสต์ก่อน/หลังเวลาเปิดทำการ
2. ออกแบบกรณี false positive ของร้านค้า โรงเรียน หรือสำนักงาน แล้วเขียนบันทึกการปรับกฎ
3. ทดลองสร้างบัญชี Analyst และยืนยันว่าเรียก Admin API ตรง ๆ ไม่ได้
4. ทดสอบหน้าเว็บบนโทรศัพท์จริง เก็บภาพและผลการทดสอบเป็นหลักฐานเพิ่มเติม
5. ทดสอบ PostgreSQL ในเครื่องและเพิ่มผล migration/integration tests ก่อนอ้างว่ารองรับจริงครบเส้นทาง
